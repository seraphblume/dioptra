# v0.2.0 Cohort B freeze contract

Baseline repository commit: `ee357ad` (`Fix v0.2 autorefractor input field mapping`).

## Candidate transition — 2026-10-16

The owner requested promotion of the existing v0.3 candidate. New cases now use v0.3.0 as primary, `schema: "dioptra-case-2"`, and `cohort: "v0.3-candidate-1"`. The frozen v0.2 engine runs in shadow. This explicitly ends new collection under the Cohort B path in this app; it does not assert that any historical cohort has been exported or calibrated.

The v0.2 engine files and historical records remain unchanged. The study CSV header is preserved and its algorithm-version column distinguishes records. Candidate statistics exclude historical cases. The comparison CSV appends cohort/schema, mm distance, and previous-Rx columns. Final-axis entry now supports 1° for the active candidate. All v0.3 offsets retain their original prior values.

## Frozen behavior

- version: `0.2.0`;
- sphere: selected AR sphere −0.25 D, quantized to 0.25 D;
- cylinder: selected AR cylinder, quantized to 0.25 D;
- axis: selected AR direction, quantized to the nearest 5° on a 180° circle;
- VA and pinhole: recorded but do not alter sphere;
- ADD: current age/refractive-state lookup;
- SE: monitoring/guardrail, with automatic AR-to-prediction shift capped at ±0.25 D.

## Change policy during Cohort B

Allowed without ending the cohort:

- documentation;
- tests that assert existing behavior;
- analysis scripts that do not alter collection or prediction;
- future schemas and design notes clearly marked inactive.

Not allowed:

- changing `js/config.js` heuristic, bins, ADD table, steps or thresholds;
- changing the prediction path in `js/algorithm.js`;
- using newly collected clinical fields in prediction;
- changing active data-entry semantics or CSV columns without a new schema/version and explicit cohort transition;
- selecting thresholds from partial Cohort B outcomes.

Emergency defect fixes must be documented, tested and versioned. If a fix changes an already locked prediction for the same input, it ends strict comparability and requires a new algorithm version/cohort boundary.

## Work done around the freeze (v0.3 shadow release)

The original shadow release kept every frozen element intact (historical behavior before the candidate transition above):

- `js/config.js` and `js/algorithm.js` are byte-identical to the frozen baseline;
- the v0.2 engine still produces the locked study prediction (`DIOPTRA_V03_CONFIG.mode = "shadow"`);
- the study record fields and the study CSV columns are unchanged (asserted in `tests/export-and-fit.test.js`);
- the final-axis picker stays at 5° steps (`ui.finalAxisStep = 5`).

Added, all outside the prediction path:

- the v0.3 engine, computed in shadow and stored under `shadow` with `shadowOnly: true`;
- optional entry of repeat readings, reliability digits, vertex distance, PD, near distances and keratometry, stored only in the shadow record;
- cylinder-aware scoring and a separate engine-comparison CSV;
- an offset-fitting tool that refuses Cohort B data until it is passed `--cohort-closed`;
- a redesigned interface. Data entry for the frozen fields keeps its semantics; the ADD picker now also offers +3.25 and +3.50.

## Verification

Run:

```sh
node tests/v0.2-freeze.test.js
```

The test loads the production configuration and algorithm, verifies the frozen configuration and checks representative predictions, axis circularity, VA/pinhole non-intervention, ADD lookup and the SE cap.

The same check runs in GitHub Actions on every push to `main` and every pull request.
